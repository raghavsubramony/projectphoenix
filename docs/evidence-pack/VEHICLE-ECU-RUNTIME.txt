VEHICLE-ECU-RUNTIME
Phoenix V3.1 — Layer-2 code that runs on the vehicle ECUs
Date: 2026-07-30
Flash ID: PHOENIX-V31-ECU-R3

PURPOSE
  Separate production ECU software from the ATPE Brain / digital twin.
  Brain emits setpoints. ECU applies, rate-limits, watches deadlines,
  validates sensors, and fails safe. Actuators never take AI commands
  without ECU ack.

PACKAGE
  ecu/                     Python reference runtime (source of truth)
    identity.py            Flash ID + build fingerprint
    limits.py              Shared thermal / watchdog / sensor / shutdown constants
    bus.py                 Fixed message contract (ModeCode + SafeMode)
    dtc.py                 Latched diagnostic trouble codes
    sensors.py             Freshness + channel validity assessment
    domains.py             Motion / Combustion / Generator / Buffer laws
    brain_bridge.py        BrainCommands → BrainSetpointFrame
    runtime.py             VehicleEcuRuntime.tick() @ 10 ms
    watchdog.py / safety.py
  firmware/c/              C skeleton for microcontroller flash
    ecu_bus.h              Same ModeCode + frame layout + limits
    ecu_runtime.c          Minimal slew + buffer clamp + EMERGENCY_OFF

CONTRACT
  Slow loop (Brain → ECU):  BrainSetpointFrame  (~50–100 ms)
  Fast loop (ECU → plant):  ActuatorCommand     (10 ms)
  Latency budget:           ≤ 50 ms end-to-end apply (soft flag; does not trip)
  Watchdog:                 cycle overrun or brain timeout → EMERGENCY_OFF (sticky)
  Operator / Mode OFF:      CONTROLLED_SHUTDOWN ramp (~100 ms) then OFF
  Sensors:                  stale > 50 ms → inhibit + P1101_SENSOR_STALE
  Thermal inhibit:          wall > 205 °C disables slot locally
  Buffer:                   brain_safe=False cuts assist/burst/precharge
  Recover:                  clear_faults() / ecu_reset_watchdog() required
